============================================================================================
第14の検証レンズ: 配信面の自己完結性 —— アプリが素朴な語根置換で再現できるか (2026-07-26 第27回続36)
============================================================================================

直前にユーザーから『注入版マスターとエクスポートの食い違い17件』の報告があり、原因は
エクスポートが4時間古かっただけ(18:17生成 vs 注入22:12生成)だった。その中で ace/ ato/ は
食い違いではなく、**アプリ側が `ace/` を ac+e、`ato/` を at+o と再分解して語根置換した結果**
(ac=科ᴬ・at=被 は実在の割当)だと判明した。
そこで本レンズでは『配信されたデータだけでアプリが正しく再現できるか』を初めて悉皆で測る。
これまでの13レンズは全て生成側(注入・台帳・原本)の中だけを見ており、配信面は測っていなかった。

--------------------------------------------------------------------------------------------
[14-1] ★素朴な語根置換の再現率は層順どおり単調
--------------------------------------------------------------------------------------------

  『素朴置換』の定義 = アプリが実装しうる最小の描画:
    見出しを空白で語に・スラッシュで分節に割り、各分節を sidecar の 語根→disp で置換するだけ。
    引けなければラテンのまま。§7の語頭大文字ガードだけは実装済みとして有利側に倒す。

     版        見出し    再現できた        再現不能
     --------- ------- ---------------- --------
     学習者版   62,111   59,103 (95.16%)    3,008
     学術版     62,111   60,567 (97.51%)    1,544

     層別(学習者版)          層別(学術版)
       CSV2890  99.27%  (不能   21)   CSV2890  99.58%  (不能   12)
       PEJVO    95.90%  (不能 1703)   PEJVO    97.39%  (不能 1084)
       PIV      92.72%  (不能 1284)   PIV      97.46%  (不能  448)

  ★CSV2890 > PEJVO > PIV で単調(学習者版)。最優先層は素朴置換でも99.3%が正しく出る。
  ★学術版のほうが再現率が高いのは、分解が粗く文脈依存処理の出番が少ないため=設計どおり。

  CSV2890層の再現不能21件(学習者版)は全件確認したが、**すべて注入側が正しく素朴置換が誤る**:
    au^t/o/mobil/o  注入=车/o/动ᴹᴮ/o   ← 素朴=车/o/挂饰/o (モビール!)
    tele/gram/o     注入=远/图ᴳᴹ/o     ← 素朴=远/克/o     (グラム!)
    c^ar/o          注入=车ᶜ̂/o        ← 素朴=因/o       (接続詞ĉar)
    c^iel/o         注入=天ᶜ̂/o        ← 素朴=全样/o     (相関詞ĉiel)
    karp/o【解】     注入=腕ᴷ/o         ← 素朴=鲤/o       (コイ)
    log/i           注入=诱ᴸ/i         ← 素朴=学家/i     (学者)
    fon/o/graf/o    注入=声ᶠᴼ/o/记ᴳ/o  ← 素朴=底ᶠᴼ/o/记ᴳ/o
    ajn / an/o / en 注入=任 / 员/o / 内 ← 素朴=引けない(1分節見出しで語尾と誤認)

[14-2] 配信面の落とし穴を悉皆で測った
--------------------------------------------------------------------------------------------

  ① 同一見出しが複数行 = 258種(学習者版)。うち **描画が違う=13種**
     → アプリが『見出し→描画』の辞書を作ると、この13種は片方が失われる。
       alkohol/at/o 醇/盐ᴬ|醇/被 ・ de/bat/i 从/辩ᴮ|从/打 ・ dur/o 币|硬ᴰ ・ hero/in/o 杰/女|杰/in
       kal/oz/o 茧/糖ᴼ|茧/oz ・ karp/o 鲤|腕ᴷ ・ kat/et/o 猫/小|股/小 ・ kub/a latin|方ᴷ
       lup/in/o 豆ᴸᵁ/in|狼/女 ・ rut/in/o 草ᴿ/女|草ᴿ/in ・ te/ism/o 神ᵀ|茶 ・ temp/er/o latin|时/粒
       torn/ad/o 车ᵀᴺ/行|旋/行 ・ log/o 学家|诱ᴸ
     ⇒ いずれも **語釈scopedで正しく弁別している同綴2義**。見出し文字列だけでは原理的に区別不能。
       app側は『版＋原本行番号』か『語釈』で sense を弁別する必要がある。
  ② 表層(スラッシュ除去)が同じで描画flatが違う = 13種(学習者版)/29種(学術版)
  ③ 末尾スラッシュ見出し(PIV接頭辞定義行) = 100行(うち漢字描画あり56)
     → 『ace/』は分節 ace + 空分節 であって ac+e ではない。空分節をまたぐ再分割は禁止。
       これが今回 ace→科ᴬ・ato→被 になった直接原因。
  ④ 分節数=トークン数の1:1整列が崩れている行 = **0**(両版) → 方針§14の主張を配信面でも再確認。
  ⑤ 分割実装が壊れやすい見出し: 空白入り6,075行 / ハイフン入り594行 / 語頭大文字4,882行

[14-3] ★恒久化した3つの仕組み
--------------------------------------------------------------------------------------------

  (1) `_gen_export.py` … 配信物の生成器を正典化(従来は手作業でscratchpadにあった)。
      生成物は3つ:
        ・_漢字割当エクスポート_学習者版/学術版_20260723.tsv (4列・既存形式のまま=互換)
        ・_漢字割当エクスポート_同一見出し衝突_20260725.tsv (版+原本行番号+語釈つき。10→13見出し44行に更新)
        ・_漢字割当エクスポート_素朴置換の危険リスト_20260726.tsv ★新規
  (2) `_audit_export_sync.py` = **[L]監査**を新設し `_verify_all.ps1` に組込。
      注入(authoritative)とエクスポートを1行ずつ突き合わせ、食い違えば fail。
      正本(DICT)のドリフトは [D] が捕まえるのに、**配信面には検出器が無かった**のが今回の事故の構造。
      検出テスト: エクスポートを1行だけ書き換えると `★描画が食い違う行=1` を報告し exit 1 することを確認。
  (3) 危険リスト 4,552行(両版) の内訳:
        ★偽の友(注入はラテンだが素朴置換は漢字を当てる) =   45行 ← アプリが誤読を生む最危険
         別の字になる                                = 3,695行
         取りこぼし(注入は漢字だが素朴置換は引けない)      =   812行 (描画が減るだけで無害)
      ★偽の友45行の例: alk/an/o→驼鹿(ヘラジカ)/an ・ fen/ol/o→焚风(フェーン)/比 ・
        tio/keton/o→那o(あれ)/keton ・ umbr/a→鱼ᵁ(魚) ・ klement/in/o→klement/女 ・
        ar/in/o→群/女 ・ di/en/o→神/en ・ kub/a→方ᴷ ・ lombard/a→当ᴸ ・ nau^t/o→航ᴺᴬ
      = いずれも過去の偽友スイープで注入側が正しくラテンへ退避させた箇所。

  ⇒ **結論: エクスポートTSVの2列目をそのまま使えば再現率100%**。語根置換は原理的に不可。

[14-4] ★副産物: 文脈規則の誤爆を622件から3件検出して是正した
--------------------------------------------------------------------------------------------

  『素朴置換なら語根本来の字になるのに注入は別の字を出している』箇所は、裏返せば
  **文脈規則(homonym sep/comb・化学塩・医学-itis・天干・語釈scoped)の誤爆候補**でもある。
  CSV2890+PEJVO層の622件を12バッチに分けて多エージェントで判定し、各主張を敵対検証した。
    → 主張3件・**確定3件**(棄却0)。622件中619件は文脈規則が正しく働いていた。

    ① neu^ton/metr/o  计ᴹ → **米**   【理】ニュートン・メートル(N･m トルクの単位)
    ② om/o/metr/o     计ᴹ → **米**   【理】オーム・メートル(Ω･m 抵抗率の単位)
       台帳は「非計器の -metr- は sep で米」と定めているが**語リスト方式のため取りこぼし**、
       comb metr→计ᴹ(計器)に流れて『ニュートン計器』『オーム計器』になっていた。
       兄弟の kilo/gram/metr/o は 千ᴷᴵ/克/米 と正しく米で、扱いが食い違っていた。
       是正は語釈scoped(『メートル（』)。両版で該当11行のうち9行は既に米=結果不変、2行だけが是正。
       同綴の om/o/metr/o【理】オーム計(計器)は不発火で 计ᴹ 維持。
    ③ log/o(魅力,魅惑,誘惑) 学家 → **诱ᴸ**
       台帳の log→诱 語リストに log/i・log/aj^/o・log/il/o・log/bird/o 等は載るのに、
       **裸名詞 log/o だけが漏れて** -log(学者)の 学家 のままだった。
       両版で『log分節＋語釈に魅力/魅惑/誘惑』の行は10行あり9行が既に诱ᴸ=1行だけ取り残されていた。
       同綴3行(【海】測程器・【聖】容量単位)は不発火で 学家 維持
       (適切な既存字が無いため2026-07-26ユーザー裁定『置換できる時だけ是正』に従い現状維持)。

  ★実装上の落とし穴をもう1つ発見: `$rest` は **コロンを含む語釈全体**($line.Substring($ci))なので
    `^魅力` のような先頭アンカーは効かない。初回実装で実際に不発火となり、出力実測で気づいた。
    (第13レンズの『elseifチェーンの順序で dead code になる』に続く2つ目の同種の罠。両方コメント常駐化)
