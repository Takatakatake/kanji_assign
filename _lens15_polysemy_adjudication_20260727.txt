第15の検証レンズ: 一語根多義の裁定線 —— 「字種を増やさない」と「全く別義なら別割当」の境界 (2026-07-27 第27回続37)
================================================================================================

ユーザーの原則(今回明示された):
  「偽分解は可能な限り尊重してほしいし、場合によっては、偽分解を超えて分解しての割り当てもして欲しい。
    一つの語根に複数の全く異なる意味が存在する場合は、基本的には、可能な限り解釈を頑張って、
    割り当て漢字の種類を増やさないように努めてほしいが、全く意味が異なる場合は、
    新たな割り当ての検討も致し方ないと考えている。」

この原則は【二方向のコスト】を同時に課す。本レンズは初めてその両側を悉皆で数えた。
  (甲) 分けた側のコスト = 字種と識別子。増やしすぎていないか。
  (乙) まとめた側のコスト = 誤読。全く別義を1字に押し込んで偽の友を作っていないか。
これまでの14レンズは (甲)(乙) のどちらも測っていない(被覆・構造・一意性・配信面が対象だった)。

------------------------------------------------------------------------------------------------
[15-1] (甲) 分けた側 —— 字種の投資は最優先層に集中していた
------------------------------------------------------------------------------------------------

  注入出力の分節→トークンを1:1で突き合わせ(整列崩れ0)、識別子を剥がした素の字で数える:

     漢字描画された語根          10,643
     うち2字種以上を持つ語根        138 (1.30%)   ← 1字種 10,505 / 2字種 123 / 3字種 14 / 5字種 1(log)

     層別   CSV2890  漢字語根 2,746  うち2字種以上  71 (2.59%)
            PEJVO    漢字語根 4,364  うち2字種以上  34 (0.78%)
            PIV      漢字語根 3,533  うち2字種以上  33 (0.93%)

  ★『増やさない』は 98.7% の語根で守られている。そのうえで **字種の追加投資は最優先層に3倍集中**
    (CSV2890 2.59% vs PEJVO 0.78%)。読まれる回数が多い語根ほど誤読の被害が大きいので、
    限られた字種予算を最優先層に割く配分は優先順位の方針と一致する。

[15-3] ★核心: 台帳が裁定済みの第2義が、描画に届いていなかった(実現率18.2%)
------------------------------------------------------------------------------------------------

  台帳 _homonym.tsv の **amb 行** は「この綴りには全く別の第2義があり、この漢字を当てる」という
  裁定の記録で、識別子まで計算済み(=その漢字の群のid空間を実際に消費している)。
  ところが amb は設計上【注入非適用】で、語釈scopedの個別ルールを手書きした数件しか発火していなかった。

     amb行 43件 / 語釈キーワードに該当する分節出現 121 / うち台帳の字で描画済み 22 = **18.2%**
     30語根が実現率ゼロ。

  その結果、配信データに残っていた偽の友(抜粋):
     mat/o     【遊】チェスの詰み          → 席   (マット・敷物)
     pat/i     【遊】ステールメイトである   → 锅   (フライパン)
     vat/o     【理】ワット(W)            → 棉   (綿)
     luks/o    【理】ルクス(照度)          → 奢   (ぜいたく)
     kuri/o    【理】キュリー(放射能)      → 廷   (古代ローマのクリア)
     stok/o    【理】ストークス(動粘度)    → 储ˢ  (在庫)
     rod/o     【海】停泊地,投錨地         → 啃   (かじる)
     bit/o     【海】繋柱(ビット)          → 位ᴮ  (情報のビット)
     sinus/o   【数】サイン(正弦)          → 洞ˢ  (解剖の洞)
     mark/o    【貨】マルク(ドイツ)        → 标ᴹ  (しるし)
     kanon/o   【キ】聖書正典              → 炮   (大砲)
     spin/o    【理】スピン                → 脊   (背骨)  ※兄弟 spin/momant/o は既に 旋ˢᴺ
     sol/o     【化】ゾル                  → 唯   (ただ一つ) ※兄弟 aer/o/sol/o は既に 胶ˢ

  ★構造的な原因は2つ、どちらも機構の欠陥だった:
    ①**行単位の全か無か判定**: _build_homonym.ps1 は行ごとに sep(注入する)/amb(しない)を自動判定するが、
      判定材料は語リスト先頭の1見出しだけ。bare見出しが『第1義と第2義の同居行』だと、
      その語根の**派生語まで丸ごと**注入非適用に落ちていた(plum/amik/o・mat/i・kanon/ec/o・orkid/it/o…)。
    ②**同綴判定が大文字小文字を無視**: 判定は PowerShell の -match で行うため §7固有名の見出しが
      『同綴2行目』に数えられていた。実害4行 —
        rod/o(停泊地) ↔ Rod/o(ロードス島) / siren/o ↔ Siren/o / po/o ↔ Po/o(ポー川) / male/o ↔ Male/o(マレ)。
      固有名は§7で必ずラテン描画になるので同綴衝突の相手にならない。-cmatch(大小区別)が正しい。

[15-4] 是正: 新字ゼロ・新規識別子ゼロで、台帳の裁定を描画に通した
------------------------------------------------------------------------------------------------

  漢字も識別子も **台帳から引く**($hsegDisp)ので、字種は1字も増えず識別子も1つも増えない。
  再生成後に (分節,漢字)→disp を全件比較して **識別子の変化=0 / 新規キー=0 / 消失キー=0** を確認済み。

  (a) _build_homonym.ps1: -match → -cmatch(固有名の巻き添えを止める)。
      巻き添えが外れた4件のうち rod だけが sep に復帰(=停泊地→泊)。siren/male は行自体が
      第1義と第2義の混在、po は disp が数字id(草ᴾᴼ2=注入不可)なので $forceAmb で amb を維持。
  (b) _build_homonym.ps1: 見出しが一意な派生語に語リスト(sep)を与えた5語根
      plum→笔(11語) / mat→将(3語) / kanon→典(4語) / orkid→丸(3語) / jard→杆(1語)。
  (c) _inject_final.ps1: **表駆動の語釈scoped機構 $ambRule を新設**(19件)。
      見出しが同綴2行あって語リストでは弁別できないものだけを、語釈キーワードで弁別する。
      従来のような elseif の手書き分岐を19本増やすのは過去2回の事故(dead code・アンカー誤り)を
      繰り返すので、台帳を引く表1つに集約した。キーワードは全て実データで発火行を全数確認(誤爆0)。

  ★触らなかったもの(角を矯めて牛を殺さないため):
     1行の中に第1義と第2義が同居する行は **第1義を維持**。トークンは1分節に1つしか出せないので、
     ここを触ると第1義が壊れる。該当14見出し —
       plum/o(羽根,羽毛;鵞ペン,ペン) orkid/o(【植】ラン;【解】睾丸) jard/o(ヤード;帆桁)
       siren/o(サイレン;カイギュウ) male/o(木槌;馬鼻疽) ergot/o(麦角;蹴爪) panikl/o(皮下脂肪;円錐花序)
       prim/o(素数;一時課) abak/o(そろばん;冠板) klik/o(爪;徒党) tof/o(凝灰岩;痛風結節)
       fon/o(背景;ホン) lir/o(【楽】リラ=琴は第1義で正) kanon/ist/o(砲手;教会法学者)
     これらは amb 行として『裁定は済んでいるが描画には出さない』状態のまま維持する。
